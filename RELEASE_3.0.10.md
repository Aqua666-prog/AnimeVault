# AnimeVault 3.0.10 (70)

## Подтверждённая причина

В Actions #102 (run 40114279547) build завершился успешно, как и onboarding
API 24/35. Артефакт APK скачан publish-job. Тег v3.0.9 и собственный draft
созданы, но assets остались пустыми.

GET releases/tags/v3.0.9 возвращает HTTP 404, тогда как GET releases содержит
этот draft (id 422865794). Скрипт ошибочно использовал первый endpoint сразу
после создания draft и останавливался до загрузки APK/JSON.

## Изменение

После 404 по тегу выполняется аутентифицированный поиск по всем страницам
списка releases. Он используется и при возобновлении, и после создания draft.
401/403/сетевая ошибка списка продолжают останавливать публикацию. Ограничения
на чужие draft, SHA тега, версии и опубликованные assets не ослаблены.

Добавлены три теста: draft на второй странице, ошибка доступа при чтении списка,
полный путь create → скрытый draft → list lookup → upload → publish.

Версия повышена с 3.0.9 (69) до 3.0.10 (70), чтобы следующий main создал новый
тег. Старый v3.0.9 уже относится к прошлому SHA и не переносится. Его черновик
не удалялся и не редактировался. Приложение, ключ подписи, SDK, зависимости,
плеер, источники и workflow остаются прежними.

## Проверки

- 16 publisher-тестов, 14 version-тестов и 7 manifest-тестов: проходят.
- CLI версии подтверждает 3.0.10 (70) / v3.0.10.
- Python-синтаксис, verify-final.sh, git diff --check: успешно.
- GitHub проверен только чтением статусов, логов и метаданных релизов.

Реальной публикации этим исправлением ещё не было. Gradle, SDK, эмуляторы,
APK-сборка в Codex и ручной запуск Actions не выполнялись. Конечный результат
публикации должен подтвердить новый автоматический запуск после слияния.
