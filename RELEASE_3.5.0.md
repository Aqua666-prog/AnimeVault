# AnimeVault 3.5.0 (78) — Cinematic UI Phase 3

База: origin/main 521f294 (3.4.0/77), Phase 2 включена. Этот этап повышает каноническую версию до 3.5.0/78. Не опубликован; сборка и проверка нового артефакта выполняются только GitHub Actions.

## Реализовано

- LibraryHubScreen: сохранённые состояния сетки, масштабирование по font scale, вычисление счётчиков категорий вне scroll frames, общий VaultPosterCard со статусами, доступ к продолжению в обычных и пустых категориях. Продолжение использует прежний stableKey и callback. ContinueWatchingCard получил опцию заполнения ячейки без изменения обычных горизонтальных полок Home.
- LibraryScreen: адаптивная плотность существующих grid/compact режимов и сохранение восстановленной позиции при первом открытии после Back. Все SAF/SmartCollection/sort/list действия остаются прежними.
- OnlineLibraryScreen: сохраняемая вкладка, отсутствие начального сброса восстановленного scroll, более читаемые метаданные, компактный постер при большом шрифте и общий VaultArtwork вместо отдельного image path.
- OnlineCatalogScreen: сворачиваемые фильтры, отдельная кнопка истории, scrollable command chrome ограниченной высоты и IME padding. Grid/list, provider/all sources, history/recent, подсказки, local matches, presets, сортировка и диагностика сохранены. Начальное восстановление позиции, завершение refresh и пагинация не сбрасывают grid; изменение выбранных фильтров/запроса сбрасывает один раз. Видимая выдача memoized по реальным зависимостям фильтрации. Частичная ошибка обозначена над доступными результатами.
- CatalogAdvancedControls: вторичные действия располагаются вертикально для большого шрифта; строка выбора жанра минимум 48dp. Client-side ограничение advanced filters по загруженным страницам сохраняется.
- DownloadsScreen: тональная сводка, пять отдельных счётчиков, читаемые метаданные и состояния, отдельные строки объёма и доступных действий. Десять статусов сохраняют прежние подписи и action gates; пауза, продолжение/повтор, просмотр и подтверждение удаления вызывают существующий ViewModel.
- DownloadsPresentation: новые счётчики working/waiting/paused, MISSING в errors, проверка конечного измеренного прогресса. Старый фильтр «В процессе» продолжает включать paused/removing; детальная сводка разделяет состояния. REMOVING остаётся доступен через «Все» и «В процессе», его удаление повторно отключено.
- Общий VaultFilterChip имеет минимальную высоту hit target 48dp. Новых библиотек, постоянных анимаций и новых настроек отображения нет.

Полная [карта исходных функций и QA](docs/design/cinematic-ui-phase3.md).

## Достоверность данных

Проценты отображаются по DownloadEntry, при неизвестной длине и отсутствии измеренного прогресса остаётся статус этапа. Скорость берётся только из положительного speedBytesPerSecond; ETA требует положительных etaSeconds и скорости и отображается только в DOWNLOADING. Завершённые задания не получают синтетическую скорость или ETA. Новые presentation-тесты проверяют MISSING, все группы статусов, NaN/неизвестный/измеренный прогресс.

Нет новой классификации сетевых ошибок по тексту. «Пусто», source error, partial и provider health используют существующие данные и сообщения; состояние offline/auth не выдумывается по пустой выдаче. Работа Tenrai, AniList, Shikimori и видеопровайдеров не гарантируется одной проверкой UI.

## Что сохранено

ViewModel библиотеки, каталога и загрузок, SearchHistory, CatalogAdvancedDiscovery, network APIs/parsers, дедупликация/aliases/fuzzy/local search, поколения запросов, кеши, очередь WorkManager/HLS/MP4, Room/backup, player, updater JSON, applicationId/minSdk, подпись, секреты и GitHub Actions не изменены. Reset использует прежний onResetDiscovery, который не очищает запрос; смена провайдера сохраняет исходную семантику. CSV, пользовательские списки, история, оценки, папки и коллекции доступны прежними маршрутами.

Стабильные ID используются в lazy items; callback identities загрузок memoized по ID, без захвата изменяющегося progress snapshot. Полная изоляция recomposition всех строк и прирост скорости не заявляются без измерений.

## Preview и проверки

MediaHubPreviews: заполненная/пустая/большая библиотека, loading, поиск/фильтры/error/partial каталога, все десять состояний загрузок и длинные названия. Размеры 320/360/600/840dp, landscape, fontScale 2, REDUCED/OFF. Локальные модели не создают repository/ViewModel и не выполняют сеть; постеры отсутствуют, VaultArtwork имеет inspection guard. Preview созданы, но не отрендерены в Codex.

Локально выполняются только статические проверки: git diff --check, lexical delimiters/duplicate imports, проверка локальных ссылок, source-version и changed-path scope. Kotlin unit-тесты добавлены, но не запускались. Gradle, Android tests и APK в Codex не запускаются; статическая проверка не означает успешную компиляцию.

Остаются compile/unit/lint/APK/signature/metadata/API24/35 в Actions и ручные сценарии из карты QA. Проверить ещё размер панели при открытой клавиатуре, длинные source/error labels, reset во время debounce, возврат из тайтла, недоступный источник, большие списки, все действия загрузок и сохранение данных при обновлении с 3.4.0. Измерить контраст и TalkBack, FULL/REDUCED/OFF, темы и fontScale 1–2. Настройки Midnight/Dynamic сохранены; их отдельные палитры по-прежнему не заявляются работающими.

## Выпуск

Прямая отправка main только без force push; при запрете — один PR. Автопубликация, тег и GitHub Release не создаются. После CI владелец отдельно разрешает ручной выпуск v3.5.0, используя APK/JSON одного SHA и прежний сертификат по [существующему порядку](docs/AUTOMATIC_RELEASES.md).
