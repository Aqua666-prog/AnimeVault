# AnimeVault 3.3.0 (76) — Cinematic UI, Phase 1

Статус: подготовка выпуска, не опубликован. Вердикт: **READY WITH RISKS** для PR; до публикации нужны сборка нового коммита и ручное QA. База — актуальный main `ddc2b160650bb45738e2536390ad517d20c0f91c`, включающий Phase 1 из PR #27 и проектный дизайнерский навык из PR #26. «Cinematic UI 4.0» — название направления дизайна; версия приложения — 3.3.0.

## Реальные изменения относительно 3.2.1

- Общий VaultAdaptiveHero на главной вместо отдельного hero фиксированной высоты. На узком экране и при большом шрифте постер располагается над текстом; на широком окне используется более крупный постер.
- Более плотный scrim за текстом и стабильная геометрия отсутствующей обложки с нейтральной иконкой. Система получения изображений не заменялась.
- Заметные карточки продолжения с названием, серией и прогрессом. Для featured онлайн-релиза с соответствующим сохранённым прогрессом используется прежний callback продолжения нужной серии.
- Адаптивная lazy-сетка рекомендаций, более читаемые метаданные и статусы, основанные на существующих данных: просмотр, библиотека, онгоинг.
- Статические placeholders загрузки, пустая подборка с переходом в каталог, ошибка с повтором и сохранение доступного контента при частичном отказе.
- Более крупные подписи навигации, фиолетовое выделение выбранного раздела, семантические заголовки и полные названия карточек.
- Ограниченный fade появления, прежние press feedback и shared poster transitions; декоративные translation/scale отключены вне FULL. OFF показывает конечное состояние прогресса и переходов.
- Автономные Preview: обычные/длинные названия, отсутствующий постер, продолжение, empty/error/loading/partial, 320/360/600/840dp, landscape, font scale 2, REDUCED/OFF. Наличие Preview не доказывает качество рендера или TalkBack на устройстве.

Техническая карта компонентов: [Phase 1 handoff](docs/design/cinematic-ui-phase1.md). Общие hero/artwork/card изменения также затрагивают переиспользующие их страницы тайтла и библиотеки. Полный редизайн этих экранов, загрузок, поиска или плеера не заявляется.

## Данные, APK и встроенное обновление

Этот PR изменяет в app/build.gradle.kts только versionName на 3.3.0 и versionCode на 76. Android UI и бизнес-логика не меняются. applicationId/namespace com.sergey.animevault, minSdk 24, target/compile SDK, build types, signingConfigs и зависимости сохранены. Изменений Room, миграций, backup-формата, preferences, разрешений и manifest нет; новые миграции для повышения версии не требуются.

Updater по-прежнему требует новый versionCode, тот же пакет и того же подписанта. Формат animevault-update.json остаётся schemaVersion 1; JSON, SHA-256 и badging генерируются существующим workflow из нового APK. Нельзя менять версию или SHA-256 в старом артефакте. 76 > 75 удовлетворяет проверке новизны; совпадение сертификата и установка поверх 3.2.1 требуют проверки нового APK.

Пути keystore, alias и секреты не менялись. Успешный CI базового main проверял прежний signing flow; это не замена проверки артефакта 3.3.0.

## Проверки и ограничения

Базовый main ddc2b16: [Actions run 40684496121](https://github.com/Aqua666-prog/AnimeVault/actions/runs/40684496121) завершён успешно, включая build и onboarding API 24/35. Этот результат относится к 3.2.1 (75) с Phase 1, а не к новой версии 3.3.0.

Для подготовки выполнены только лёгкие локальные проверки: source-version validator для v3.3.0, 14 Python tests release validation и 18 offline tests исторического publisher (fake GitHub, без публикации), 7 tests генерации update-манифеста, Markdown-ссылки, точный diff двух version-полей и git diff --check. Gradle, APK и instrumentation в Codex не запускались. Статическая проверка не считается успешной компиляцией.

До публикации требуется:

1. Собрать выбранный SHA только в GitHub Actions; пройти compile, unit tests, lint, APK/signature/metadata checks и существующие API 24/35 tests. Для workflow_dispatch на ветке PR указать release_tag=v3.3.0: это вход проверки версии, а не создание тега или релиза.
2. Сверить packageName, versionName 3.3.0, versionCode 76, minSdk 24, SHA-256, JSON и сертификат APK с установленной 3.2.1.
3. Проверить обновление поверх 3.2.1 без удаления данных: библиотека, избранное, прогресс и настройки; затем local/online resume, поиск, загрузки и Back.
4. Выполнить ручную приёмку главной и общих карточек/тайтла: маленький экран, планшет, landscape, большой шрифт, TalkBack, контраст на ярких постерах, FULL/REDUCED/OFF и системное отключение анимаций.

Midnight и Dynamic сохраняются в настройках, но AnimeVaultTheme отдельно обрабатывает только OLED относительно базовой Vault. Полноценные Midnight/Dynamic, ускорение приложения и полное завершение редизайна не заявляются.

## Только ручной выпуск

Workflow и [порядок ручного выпуска](docs/AUTOMATIC_RELEASES.md) не меняются. Автопубликации нет; этот PR не создаёт тег, draft или опубликованный GitHub Release и не объединяется автоматически.

При отмене выпуска оставить опубликованную 3.2.1 доступной; после распространения code 76 не переиспользовать.
