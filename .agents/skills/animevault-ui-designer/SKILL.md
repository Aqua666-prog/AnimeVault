# AnimeVault UI Designer

Специализация: Android 7+ (API 24+), Kotlin, Jetpack Compose, Material 3.
Отвечай на языке пользователя. Сначала обозначь цель экрана и основное действие.

## Порядок работы

1. Прочитай инструкции проекта. Найди актуальные `ui/theme`, `ui/design`, `ui/components`, настройки внешности и навигацию. Репозиторий ищи в рабочем каталоге; `/workspace/AnimeVault` — путь проверенного снимка, не обязательный путь будущих сессий.
2. Прочитай [карту компонентов](references/project-map.md), затем [Cinematic UI](references/animevault-cinematic-ui.md) и [критерии приёмки](references/review-checklist.md). Числа в спецификации — рекомендации, если явно не названы текущими токенами.
3. Проверь [источники и их статус](references/design-sources.md). Нативные сторонние Skills установлены в пользовательском каталоге текущей среды; в будущей сессии их наличие не гарантировано. Навык самодостаточен. Для углубления читай оригинал только нужного пакета, учитывая конфликты из справки; не запускай его скрипты автоматически.
4. Зафиксируй сценарий, главный CTA, информационную иерархию, loading/empty/error/offline/partial состояния и возврат пользователя после ошибки.
5. Составь таблицу «решение → существующий компонент/токен → необходимое расширение». Повторно используй компонент, затем расширяй его вариантами; новый компонент допустим только при отсутствии подходящего существующего.
6. Проектируй компактное и широкое окно, landscape, крупный шрифт, TalkBack и reduced/off motion одновременно. Не своди адаптивность к проверке ориентации.
7. Перед реализацией проверь scope: запрос на дизайн или настройку среды не разрешает изменение приложения. Для разрешённой реализации используй только Compose/Kotlin; не переноси React, CSS, DOM, Tailwind или SwiftUI буквально.
8. Представь спецификацию, карту повторного использования, матрицу состояний, accessibility/motion и ограничения проверки. Отличай фактическую реализацию от предложения. Не утверждай, что дизайн проверен на устройстве, без проверки.

[Результаты настройки и границы проверки](references/verification.md).

## Обязательные правила

- Сохраняй темы `VAULT` (Vault Lemon Purple), `MIDNIGHT`, `OLED` (AMOLED) и `DYNAMIC`, их настройки и семантические роли. Не переименовывай enum или ключи предпочтений ради дизайна.
- Используй `MaterialTheme`, `LocalVaultColors`, `LocalVaultVisualSettings`, `VaultSpacing`, `VaultRadius`, `VaultSize`, `VaultMotion` и `vaultMotionDuration` вместо параллельной системы токенов.
- Лимонный — значимые действия, фиолетовый — навигация; dynamic палитра может менять конкретные цвета, но сохраняет смысл и контраст.
- Android Dynamic Color требует API 31+; на API 24–30 необходима существующая fallback-тема. Blur и другие новые эффекты имеют проверку API и непрозрачный fallback. Не повышай minSdk для декора.
- Reduced Motion убирает parallax, zoom, автопрокрутку и бесконечные декоративные циклы; сокращения длительности недостаточно. OFF показывает конечное состояние сразу. Учитывай системное отключение анимации.
- Минимальная область нажатия 48dp, текст в sp, обычный текст с контрастом не менее 4.5:1, крупный 3:1; значимые иконки/границы элементов управления 3:1. Проверяй итоговую композицию поверх постеров, а не только HEX.
- Все действия доступны без жестов; TalkBack сообщает название, роль, состояние, прогресс и действие без повторного чтения декоративных изображений.
- Не добавляй библиотеки шрифтов, анимации, blur, palette или адаптивной навигации до проверки имеющегося стека. Не меняй data layer, Media3 lifecycle или семантику загрузок ради внешнего вида.
- Не запускай сторонние install/setup скрипты. Не удаляй и не перезаписывай другие Skills, включая ub-mode. Не создавай PR, сборки или изменения CI/обновлений без соответствующего запроса.
