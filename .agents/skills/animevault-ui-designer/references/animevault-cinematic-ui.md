# AnimeVault Cinematic UI

Дизайн-спецификация, 2026-10-28. Статус: рекомендации по развитию существующей UI-системы, без изменения приложения. Проверенный исходный снимок указан в [карте проекта](project-map.md).

## Замысел и границы

Основная задача — быстро выбрать аниме и продолжить просмотр. Главный объект — тайтл, основной CTA — «Продолжить» или «Смотреть». Кинематографичность создают постеры, глубина фона, ясная типографика и переход от выбранного постера к тайтлу. Управление, загрузки и поиск остаются спокойными и предсказуемыми.

Платформа: branded native Android 7+ / API 24+, Kotlin, Jetpack Compose, Material 3. Использовать текущий стек и компоненты, не веб-шаблоны. Не требуются новые шрифты, UI kits, blur libraries или animation frameworks.

### Сохранение четырёх тем

| Тема / enum | Требование |
|---|---|
| Vault Lemon Purple / VAULT | Тёмные поверхности, лимонные действия, фиолетовая навигация |
| Midnight / MIDNIGHT | Сохранить настройку; для будущей реализации холодные глубокие поверхности с теми же ролями и контрастом |
| AMOLED / OLED | Чистый чёрный основной фон, тёмные карточки; разделение тоном/границами, не одной тенью |
| Dynamic / DYNAMIC | Сохранить настройку; системная семантическая палитра на API 31+, fallback Vault на API 24–30 |

В прочитанном Theme.kt отдельно обрабатывается только OLED; полноценные Midnight и Dynamic не подтверждены. Не выдавать эту таблицу за результат runtime-проверки. Не менять настройки или их сериализацию в рамках дизайн-предложения.

## Типографика

Использовать `AnimeVaultTypography`, системный `FontFamily.SansSerif`, sp и font scale. Не подключать SF Pro или Inter ради сходства с референсом.

| Контент | Существующий стиль | Размер / line height |
|---|---|---|
| Большой редкий акцент | displaySmall | 31 / 37sp |
| Заголовок широкого hero | headlineLarge | 28 / 34sp |
| Заголовок секции | headlineSmall или titleLarge по текущему компоненту | 21 / 27 или 20 / 26sp |
| Компактный hero | titleLarge | 20 / 26sp |
| Название постерной карточки | titleSmall | 14 / 19sp, SemiBold |
| Основной текст | bodyLarge | 16 / 25sp |
| Вторичный текст | bodyMedium | 14 / 21sp |
| CTA | labelLarge | 14 / 18sp |
| Короткие метаданные | labelMedium | 12 / 16sp |

Текущий VaultPosterCard использует labelSmall 11/15sp для метаданных. Для важных данных предпочитать labelMedium при разрешённом расширении компонента. Заголовок карточки — до двух строк, полное название доступно на странице тайтла и в семантике. Не уменьшать текст ради помещения в фиксированную высоту; при font scale 2.0 увеличивать высоты/число строк и уменьшать число колонок. Не менять существующий tracking глобально.

## Сетка и адаптивность

Текущие `VaultSpacing`: 2, 4, 8, 12, 16, 20, 24, 32dp. Основные интервалы — 8/16/24dp; поля компактного экрана 16–20dp, широкого 24–32dp. Радиусы `VaultRadius`: 8/12/16/22/28/32dp; постер 12dp, панели по роли, hero до 32dp. Не делать все контейнеры одинаковыми pills.

Рекомендуемые диапазоны считать по доступной ширине окна после insets и навигации, не по модели устройства:

| Ширина | Рекомендуемая композиция |
|---|---|
| <600dp | Один основной поток; нижняя навигация; сетка постеров обычно 2–3 колонки |
| 600–839dp | Rail; более широкая сетка; hero с большим постером; избегать растянутых кнопок |
| ≥840dp | Rail и при полезности list/detail; постеры обычно 4–6 колонок, число по доступной ширине |

Сетка: целевая ширина постера примерно 104–156dp, gap 12–16dp; число колонок уменьшать для длинных названий и крупного шрифта. Например, 360dp − 2×20dp поля − 12dp gap = две карточки по 154dp. Не жертвовать текстом ради трёх колонок. Ограничивать ширину читаемого описания, а не растягивать строку на весь планшет.
Landscape с малой высотой требует компактного hero и доступного CTA; горизонтальный телефон не становится автоматически двухпанельным планшетом. Учитывать cutout, gesture navigation, IME и fold hinge. Использовать имеющиеся bar/rail и VaultAdaptiveHero; новые adaptive библиотеки не обязательны.

## Постеры и атмосфера

- Сохранять портретный 2:3, ContentScale.Crop с контролем смыслового кадра; не растягивать изображение.
- VaultPosterCard — единый базовый компонент для главной, поиска и библиотеки. Для состояния просмотра использовать существующий WatchProgressBar, без второй независимой карточки.
- Не накладывать длинный title поверх шумного постера. Короткий статус допускается с читаемой подложкой. Декоративный постер с повторяющимся текстовым названием не озвучивать второй раз.
- Hero: VaultAdaptiveHero и VaultArtwork; backdrop приглушённый, текст защищён scrim/устойчивой поверхностью. Насыщенность иллюстрации не должна перекрашивать CTA и статусы.
- Placeholders/error сохраняют размеры и место заголовка; ошибка изображения не превращает весь тайтл в ошибку экрана. Не добавлять случайные чужие постеры вместо отсутствующих данных.
- Blur опционален и по умолчанию не обязателен; API fallback — тональная подложка. Не декодировать полноразмерные изображения для каждой карточки; использовать имеющийся Coil и размеры запроса.

| Экран | Приоритет и действие | Повторное использование / композиция |
|---|---|---|
| Главная | Быстро продолжить текущий просмотр | HomeScreen/HomeFeed, секция «Продолжить», затем рекомендации/недавнее; один hero, VaultSectionHeader и VaultPosterCard |
| Карточка аниме | Узнать тайтл и открыть детали | Постер 2:3, название, 1 строка метаданных, один значимый badge; контекстные действия доступны отдельной кнопкой/меню |
| Страница тайтла | Смотреть либо продолжить конкретную серию | VaultAdaptiveHero, основной CTA, метаданные, описание, сезоны/эпизоды; загрузка и избранное вторичны |
| Библиотека | Вернуться к сохранённому или локальному контенту | LibraryHubScreen, понятные категории/фильтры, стабильная сетка; доступность файла и прогресс видимы |
| Загрузки | Понять статус и управлять очередью | DownloadsScreen, строки с названием/серией, статусом/прогрессом, pause/resume/retry по реальной поддержке engine; декоративный hero не нужен |
| Поиск | Найти тайтл и сузить результаты | VaultSearchField, VaultFilterChip, история/подсказки, результатная сетка; различать «ничего не найдено» и ошибку источника |
| Плеер | Смотреть, менять позицию/дорожки без потери контекста | PlayerControls/PlayerChrome, читаемая подложка, 48dp controls, время/seek, субтитры и качество; advanced controls в sheet |

Не добавлять новую бизнес-операцию только ради кнопки на макете. Pause/retry/удаление и выбор источника должны отражать реальные состояния модели.

### Общая матрица состояний

| Состояние | Отображение и восстановление |
|---|---|
| Loading | Стабильные размеры skeleton; при motion OFF/REDUCED статический placeholder вместо бесконечного shimmer |
| Empty | Причина и полезное действие: найти аниме, добавить папку или сбросить фильтры |
| Error | Краткая причина и «Повторить»; различать сеть, источник, разрешение и отсутствующий локальный файл |
| Offline | Сохранённый контент доступен; явная подсказка о сети и переход в локальную библиотеку |
| Partial/stale | Показывать доступное; пометка неполных/устаревших данных и повтор только неудавшейся части |
| Success | Короткая обратная связь без блокирующего экрана; фокус и позиция списка сохраняются |

Для загрузок различать queued/running/paused/failed/completed согласно реальным моделям. Для плеера различать buffering, playback error, завершение серии и недоступный файл; UI не создаёт новый ExoPlayer ради смены внешнего состояния.

## Motion

Использовать текущие `VaultMotion`: pressIn 120, pressOut 160, fast 150, standard 240, reveal 300, hero/slow 500ms. Пропускать через `vaultMotionDuration`, состояние брать из LocalVaultVisualSettings. Не вводить конкурирующие duration constants.

| Взаимодействие | FULL | REDUCED | OFF |
|---|---|---|---|
| Нажатие | Быстрая индикация состояния; осторожный scale при наличии | Цвет/opacity без scale | Немедленное состояние |
| Постер → тайтл | Существующий shared transition, если ключи и lifecycle позволяют | Короткий fade или мгновенная замена, без zoom | Мгновенная смена |
| Hero при scroll | Сдержанный имеющийся parallax | Без parallax | Без parallax |
| Sheet | Material transition, допускающий прерывание | Минимальное перемещение/короткий fade по возможностям control | Конечное положение сразу |
| Loading | Ненавязчивое движение при необходимости | Статический индикатор с семантикой | Статический индикатор с семантикой |

Действие не ждёт окончания анимации. Быстрые повторные нажатия и системный Back не блокируются. Gesture transitions продолжаются с текущего значения; применять существующие Material/Compose механизмы, не собственный JS physics port. Нет autoplay carousel, полноэкранного движущегося фона, обязательного bounce или haptic на каждый тап. Haptic — только значимое подтверждение и с учётом настроек.

Системное отключение анимаций имеет приоритет; Theme.kt уже перечитывает его при resume. MINIMAL в текущих preferences нормализуется в REDUCED, поэтому нельзя обещать отдельную ветвь поведения без проверки. Reduced Motion — изменение характера движения, а не только множитель длительности.

## Навигация и доступность

Использовать существующие маршруты и Vault navigation shell. Нижняя панель для компактного окна, rail для более широкого, стабильные названия/порядок разделов; не добавлять Search как постоянную вкладку, если в проекте он уже встроен в каталог. Возврат сохраняет scroll, фильтры и выбор; системный Back закрывает sheet/полноэкранный режим согласно текущему flow.

TalkBack читает карточку как понятный объект: название, значимое состояние и действие. Кнопки внутри карточки — отдельные действия без вложенных конфликтующих кликов. У вкладок selected semantics, у заголовков heading, у прогресса — диапазон/текст состояния; объявления только при значимых переходах. Декоративные изображения — без contentDescription.

Любой swipe/double tap имеет доступную кнопку или semantics action. Seek сообщает позицию/длительность и допускает доступное изменение. Субтитры, контролы и системные insets не перекрываются. Размер нажатия ≥48dp; не путать визуальный размер иконки 20dp с hit target.

Обычный текст ≥4.5:1, крупный ≥3:1, значимые элементы управления ≥3:1 с окружением. Измерять финальную поверхность, включая scrim, transparency и artwork. Проверять все темы и состояния выбора; screenshot сам по себе не подтверждает TalkBack.

## Проверка и handoff

Перед реализацией предъявить карту «элемент → существующий composable/token», состояния, компактный/широкий/landscape макеты и motion variants. Новые варианты компонентов обосновать реальным различием поведения.

Для будущего QA: 320/360dp, 600dp, 840dp+; font scale 1.0/1.3/2.0; API 24 и 31+; четыре темы; FULL/REDUCED/OFF и системное animation scale 0; пустые данные, длинные названия, ошибка изображения, сеть offline, ошибка playback. Пользовательские проверки — открыть тайтл и вернуться, найти аниме, открыть локальную серию, управлять загрузкой и seek с TalkBack.

В этой задаче выполнены только статические проверки документов и исходников; визуальные макеты, screenshot/contrast measurements, TalkBack и производительность на устройстве не проверялись. Gradle, APK и сторонние скрипты не запускались.
