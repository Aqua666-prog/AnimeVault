# Обновления AnimeVault через GitHub Releases

## Текущее состояние репозитория

Проверено перед изменениями: в main версия 3.0.3, versionCode 63, package
com.sergey.animevault, minSdk 24. Опубликованных GitHub Releases нет.
VersionCode и versionName в этом PR не меняются: номер следующего релиза выбирает
владелец перед публикацией.

Основной build-apk.yml восстанавливает постоянный debug-сертификат из Secrets.
Его параметры и секреты подписи сохранены. QA workflow animetka-qa.yml не
восстанавливает этот сертификат; его APK нельзя использовать для обновления
установок, подписанных постоянным ключом. Переход на другой сертификат, в том
числе отдельно созданный release-ключ, несовместим с обновлением таких установок.

## Поведение приложения

- На главном экране выполняется проверка latest стабильного публичного релиза
  Aqua666-prog/AnimeVault, не чаще раза в сутки. Есть выключатель автоматической
  проверки и ручная проверка в «Настройки → О приложении».
- Сравнивается целочисленный versionCode, а не строка версии и не tag.
  Черновики и prerelease не предлагаются.
- Окно показывает имя версии, описание GitHub Release, размер APK и действия
  «Скачать APK», «Позже», «Не напоминать об этой версии».
  Пропущенную версию можно открыть ручной проверкой.
- Проверка и загрузка не требуют Google-входа. Сетевые ошибки не блокируют
  каталог, просмотр или гостевой режим. Окно не появляется поверх плеера.
- Загрузка идёт в приватный cache/app_updates с прогрессом и отменой.
  Неполный файл удаляется; файлы загрузчика видео не затрагиваются.
  Обновление можно свернуть и продолжить пользоваться приложением.
- После завершения процесса Android незавершённую загрузку нужно начать заново.
  Полностью скачанный APK повторно используется после ручной/следующей
  автоматической проверки, если он ещё находится в кэше и проходит все проверки.
  Фоновой службы и постоянного уведомления для APK нет.
- До готовности и повторно перед установкой проверяются размер, SHA-256, пакет,
  versionCode/versionName, minSdk и совпадение текущих сертификатов подписантов
  APK с установленным приложением (API 24–27: signatures, API 28+: signingInfo).
  Ротация ключей не поддерживается: используется существующий постоянный ключ.
- «Установить» открывает системный установщик через content URI FileProvider.
  На Android 8+ при необходимости предлагается разрешить установку именно из
  AnimeVault. Возврат из настроек ничего не устанавливает сам: нужно повторно
  нажать «Установить». На Android 7 используется системный установщик и его
  системные ограничения неизвестных источников.
- Отмена установки оставляет проверенный APK доступным для повторной попытки.
  Обновление не очищает аккаунт, БД, историю, коллекции или видео.

## Что настроить в GitHub для публикации

1. Использовать существующие GOOGLE_SERVICES_JSON_B64,
   ANIMEVAULT_DEBUG_KEYSTORE_B64, ANIMEVAULT_DEBUG_STORE_PASSWORD,
   ANIMEVAULT_DEBUG_KEY_ALIAS и ANIMEVAULT_DEBUG_KEY_PASSWORD.
   Не заменять сертификат. KODIK_API_TOKEN остаётся существующим необязательным
   параметром проекта. Новых Secrets для updater не нужно.
2. Перед каждым обновлением повысить versionCode в app/build.gradle.kts
   строго выше всех распространявшихся APK (текущий базовый код — 63).
   Также установить подходящий versionName. Сохранить package и minSdk 24.
   Скрипты verify-final.sh / verify-2.0.0.sh проверяют корректность версии,
   без прежней жёсткой привязки к 63 / 3.0.3.
3. После проверки и слияния нужного PR запустить существующий Build AnimeVault
   APK для выбранного main-коммита либо дождаться его обычной сборки на push.
   Только GitHub Actions выполняет компиляцию/сборку и проверяет подпись
   через apksigner; в среде Codex сборки не выполняются.
4. Скачать артефакт AnimeVault-debug-<commit>. Он содержит AnimeVault.apk
   и animevault-update.json, автоматически созданный из aapt badging именно
   этого APK с SHA-256 его байтов. Не переименовывать APK после создания JSON.
5. После отдельного разрешения владельца создать стабильный GitHub Release
   из нужного коммита с tag, например v3.0.4, и понятным описанием изменений.
   Прикрепить оба файла непосредственно в Assets, не ZIP с артефактом.
   Проверить, что релиз публичный, не draft/prerelease, и выбран как latest.
6. Не изменять APK/JSON опубликованного релиза. Для следующего обновления
   создать новый релиз с большим versionCode. Проверить реальное обновление
   поверх установленного APK с тем же сертификатом.

Автоматической публикации, новых tag-триггеров, workflow с contents:write
и токена GitHub внутри приложения нет. Этот PR не создаёт и не публикует Release.
Firebase Console менять для updater не требуется.

## Формат animevault-update.json

```json
{
  "schemaVersion": 1,
  "packageName": "com.sergey.animevault",
  "versionCode": 64,
  "versionName": "3.0.4",
  "minSdk": 24,
  "apkFileName": "AnimeVault.apk",
  "sha256": "<64 шестнадцатеричных символа SHA-256 APK>"
}
```

Значения выше — пример будущего релиза. Реальный JSON генерирует Actions.
Разрешены только HTTPS-ссылки репозитория и перенаправления в хранилище GitHub.
APK ограничен 300 МБ, метаданные — 32 КБ, описание — 24 000 символов.
Поддерживается один универсальный APK; split/APKS/AAB не поддерживаются.

## Проверки

Лёгкие проверки: git diff --check, просмотр diff, синтаксис Python/XML,
fixture-тесты tools/test_update_manifest.py (обычные байты, не сборка APK).

Добавлены JVM-тесты протокола релиза и ViewModel: в среде Codex не запускаются.
Стандартный GitHub Actions проверяет compileDebugKotlin, testDebugUnitTest,
lintDebug, assembleDebug после единственного итогового push; эмуляторы и
инструментальные тесты не добавлялись.

Ручные сценарии на API 24 и 26+:
- Нет релизов / та же или более старая версия: нет предложения установки.
- Новый стабильный релиз: описание → загрузка → установка поверх старой версии.
- Отказ в разрешении/отмена установщика: приложение продолжает работать.
- Отключение сети, отмена загрузки, повтор, потеря процесса, ручная проверка
  с уже скачанным APK.
- Не совпали hash, пакет, версия, SDK, подпись или размер: установка отклонена.
- Обновление сохраняет вход Firebase и локальные данные; вход не обязателен.
