# Выпуск релизов вручную

Автопубликация отключена по решению владельца. Файл сохраняет прежний путь,
чтобы существующие ссылки не сломались.

GitHub Actions продолжает compile, unit-тесты, lint, сборку с прежним ключом,
проверку подписи и согласованности APK/JSON и загрузку артефактов.
Job `publish-release` удалён. В workflow нет операции создания/публикации
GitHub Release или тега, а также токена с правами `contents: write`.

После успешной сборки:

1. Скачать артефакт `AnimeVault-debug-<SHA>` нужного коммита.
2. Взять `AnimeVault.apk` и `animevault-update.json` из одного артефакта.
3. Создать тег `v<versionName>` на SHA именно этой сборки и GitHub Release.
4. Прикрепить оба файла и опубликовать вручную.

Версию и JSON не редактировать в файлах артефакта. `apk-badging.txt` нужен
для внутренней проверки и в Release не требуется. Пользовательский updater
остаётся прежним и читает опубликованный владельцем релиз.

`tools/publish-github-release.py` сохранён как исторический инструмент с
регрессионными тестами. Workflow вызывает его только с `--print-tag` для
локальной проверки версии main — этот режим не обращается к GitHub и не
создаёт теги/релизы. Режим публикации из workflow не вызывается.
