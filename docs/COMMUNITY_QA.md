# Community: проверки и критерии выпуска

Не считать строки ниже результатами тестирования, если нет соответствующего лога CI/устройства. Gradle, SDK tools, emulator, APK install/build в среде Codex запрещены заданием и не запускались. SQL в production не применялся.

## Автоматические проверки

| Набор | Что проверяет | Где запускается |
|---|---|---|
| Python `test_community_contract.py` | callbacks, границы конфигурации/токенов, SQL grants, definer search_path | Codex/CI, лёгкие source-инварианты |
| Все существующие `tools/test_*.py` | релизные, onboarding, manifest и другие контракты | Codex/CI |
| `CommunityContractTest` | plain text, пароли, configuration, request IDs, DTO, episode cache keys, безопасные ошибки | JVM в Actions |
| `test-community-database.py` | реальные ограничения/RPC/RLS, идемпотентность, параллельный антиспам | Disposable PostgreSQL 17 в Actions |
| `CommunityAuthTest` | синтетические signup/callback/replay/login/logout/recovery/OTP/refresh/offline, Keystore restoration, Firebase isolation | Android Actions, API 24/25/35 |
| `CommunitySpoilerTest` | отсутствие скрытого body в semantics до раскрытия | Android Actions, API 24/25/35 |
| PR compile/unit/lint/assemble | все существующие JVM-тесты плюс новые, lint и APK | Secret-free `community-pr.yml` |
| Полный подписанный APK | прежний Firebase config/signing/версия/update manifest | `build-apk.yml` на feature-ветке |

Синтетические Auth-тесты не доказывают доставку писем, реальный GoTrue PKCE, настройки recovery или вход Google на настоящем устройстве. Secret-free Firebase fixture не предназначен для распространения. Новая матрица Android запускает только Community instrumentation, не заменяет прежние onboarding тесты и ручной smoke.

На снимке 14d3112 PR suite прошёл: 620 JVM, 13 SQL и по 9 Community instrumentation tests на API 24/25/35. В существующем workflow onboarding API 24 прошёл, API 35 потерял соединение с эмулятором до завершения. Окончательные результаты и ссылки на новые запуски после объединения коммитов фиксируются в PR и `COMMUNITY_IMPLEMENTATION_REPORT.md`. Недоступность runner, ошибки инфраструктуры и падения тестов не считать прохождением.

## Проверка владельцем на Android

1. Применить миграцию в staging/контролируемом проекте по SUPABASE_SETUP, назначить модератора, завести проверенный тайтл у двух провайдеров и отдельный сезон, обычную/специальную серию.
2. Установить подписанный APK из доверенного workflow; записать SHA, 4.1.0/80, модель/API, тему и сеть. Начать с API 24, повторить на 25 и современной системе.
3. Без Community Account проверить главный экран, каталог, локальную библиотеку, загрузки, воспроизведение, fullscreen, PiP, поворот и сохранённый прогресс. Проверить существующий Google/Firebase вход, выход и онбординг, затем AniList OAuth. Не принимать Firebase-сессию за Community.
4. Настройки → Аккаунт → AnimeVault Community. Зарегистрировать разрешённый тестовый email с паролем от 12 символов. Не рассылать больше квоты встроенного SMTP. Проверить отсутствие сессии до подтверждения. Открыть письмо на том же устройстве при закрытом и открытом приложении; создать профиль после callback.
5. Проверить OTP fallback при наличии `{{ .Token }}` в шаблоне, истёкшую и повторно использованную ссылку, дублированный code, другой host/path, fragment с поддельным token, ссылку с другого устройства. Ошибка должна быть понятной, без URI/token/stack trace в логах и UI.
6. Войти, выйти, войти повторно; убить процесс и проверить восстановление сессии. Проверить refresh при истечении access token, отозванный refresh, сеть во время refresh, выход офлайн, удаление черновиков после выхода. Firebase UID до/после не меняется.
7. Восстановить пароль. Проверить recovery + Secure password change/current password на реальном Supabase; пароль не должен обновляться без условий сервера. Если требуется дополнительный nonce или recovery не проходит, блокировать выпуск, не ослаблять настройки Auth.
8. Вкладка «Обсуждение»: гость читает, не пишет/лайкает/жалуется. Пользователь с профилем публикует, сохраняет переносы, видит число символов. Проверить 1/2000/2001 символ, пустой текст, Unicode, текст `<script>` как обычную строку, двойной тап и потерю ответа сервера после записи.
9. Проверить редактирование, отмену, черновик после закрытия/поворота/перезапуска. Нельзя редактировать чужой текст. Удаление требует подтверждения, сохраняет чужие ответы. До двух уровней ответов; страницы по 20, три сортировки корней, ответы по времени.
10. Поставить и убрать лайк, быстро нажать повторно; проверить одну запись на пользователя, rollback UI при ошибке и серверный счётчик. Другой пользователь не может удалить чужой лайк.
11. Спойлер скрыт по умолчанию и отсутствует в TalkBack до раскрытия. В серии показывается canonical episode number/key. Не публиковать скрытый текст в previews. Подать жалобу «Спойлер без предупреждения» и остальные причины, проверить повторную активную жалобу.
12. Через администратора проверить жалобу, hide/restore, audit log, временную/бессрочную блокировку и отмену. Проверить, что hidden body не возвращается через REST обычному клиенту и бан блокирует публикации/ответы/лайки.
13. Проверить два провайдера одного anime, отдельный сезон/ремейк, фильм/OVA, дробную серию, одинаковое название, отсутствующий ID, конфликт AniList/MAL и непроверенную связь. Общая ветка и серия никогда не смешиваются; неподтверждённое сопоставление недоступно.
14. После загрузки выключить сеть, открыть обсуждение снова: кеш с отметкой неактуальности, черновик сохранён, автоматической отправки нет. При недоступном сервере, 429, 403, ошибке конфигурации остальные функции приложения доступны.
15. Повторить на маленьком телефоне, в landscape, на планшете, с font scale 200%, TalkBack, Reduce Motion и всеми четырьмя темами, включая Dynamic fallback на API 24/25. Проверить 48dp targets, переносы, контраст, клавиатуру, back и доступность действий ниже сгиба.
16. Собрать вариант без Supabase variables: Community показывает «Сервис не настроен», приложение/плеер/медиатека не падают. Отдельно проверить удаление аккаунта владельцем и анонимизацию текста в staging.

## Условия публичного запуска

Нужны успешные Android/SQL CI, реальные device smoke/Auth/callback проверки, внешний SMTP, production Site URL, защищённые App Links, подтверждённые canonical mappings, оператор модерации, мониторинг/лимиты публичного API и проверенные backup/restore. До этого это кандидат, а не готовая публичная социальная сеть.
