# AnimeVault 4.1.2 (82) — APK для проверки Zero-Touch

Базовый main: `337b6c4111feed364a5abb8efef223a104afc3dd`, версия 4.1.1(81). Patch меняет только Android versionName/versionCode и документацию. Kotlin-код клиента, Auth/Firebase, комментарии/лайки/ответы, Media3, Room, Supabase/SQL/Edge/Secrets не изменяются.

## Что входит из PR #43

`OnlineTitleScreen` создаёт CommunityIdentity из реальных provider/release и внешних ID; `CommunityIdentityPrefetch` асинхронно вызывает общий resolver при открытии карточки. Первым идёт прежний `community_resolve`. При null для поддерживаемого общего контекста resolver под Mutex повторяет чтение и вызывает `functions/v1/community-ensure` с ограничением частоты. UUID затем повторно получается через прежний RPC; только после этого вкладка загружает комментарии. Pending даёт максимум два дополнительных read-only чтения; постоянного polling нет. Код API24+ не требует нового SDK.

Отсутствие надёжной связи/поддерживаемого proof, неподтверждённый AniLiberty bridge, специальные/неизвестные эпизоды могут оставить обсуждение недоступным. Похожее название не даёт основания объединять разные тайтлы или сезоны.

## Сборка и установка

Используется существующий **Build AnimeVault APK**, вручную для patch-ветки с `release_tag=v4.1.2` как параметром проверки версии. Это не создание Git tag или Release. Сборка использует существующие Firebase Secrets, Community publishable configuration и debug keystore владельца; PR CI APK с синтетической Firebase-конфигурацией не заменяет этот установочный артефакт.

Дождитесь зелёного полного workflow. Скачайте artifact **AnimeVault-debug-<полный SHA patch-коммита>**, внутри — `AnimeVault.apk`, `animevault-update.json`, `apk-badging.txt`. Проверка CI сопоставляет версию APK, source и JSON и проверяет подпись apksigner. Версия обязана быть **4.1.2 / 82**, package — `com.sergey.animevault`, minSdk — 24. Номер фактического run и artifact фиксируются в PR/итоговом отчёте после успешной сборки.

Сохраните свою обычную резервную копию, установите APK **поверх**, без удаления приложения/очистки данных. Старое установленное приложение должно иметь versionCode ниже 82 и ту же подпись. Workflow использует прежний keystore, но совпадение с конкретным APK на телефоне и сохранность данных при обновлении нужно подтвердить на устройстве. Если Android сообщает несовпадение подписи — остановитесь, не удаляйте старое приложение ради установки и не теряйте библиотеку.

## Проверка на настоящем Android

Владелец сообщил: миграция 003 применена; обе функции развёрнуты; MAL_CLIENT_ID настроен; Edge global gate=true; DB on_demand=true; background=false. Это контекст тестирования, а не повторная проверка/изменение сервера из Codex. Не переключайте background и не запускайте миграции/deployment ради этого APK.

1. Убедитесь, что в информации о приложении/настройках версия 4.1.2(82). Проверьте сохранённые библиотеку, историю, настройки, гостевой режим и существующий Google/Firebase вход.
2. Откройте карточку нового для Community аниме в **конкретном поддерживаемом источнике** (не synthetic Unified). Не начинайте со специальных эпизодов. Проверьте обычную загрузку карточки, затем вкладку «Обсуждение»: loading → общий UUID/пустое обсуждение при успешной независимой проверке сервера.
3. На сервере проверьте только безопасные `community_ensure` logs/status и отсутствие ошибок; не копируйте заголовки/ключи в отчёт. Рост canonical/alias относится к реальному owner-run тесту, не к сборке APK. Невозможно подтвердить identity — ожидаемо недоступное обсуждение, без чужой ветки.
4. Повторно откройте карточку: тот же тайтл должен получить прежний UUID без дубликатов. Смена озвучки Kodik с тем же shiki ID и проверенная связь другого провайдера должны вести в то же обсуждение. Разные сезоны — разные ID/обсуждения.
5. Гость читает существующие комментарии; отдельный Community Account публикует комментарий/ответ, редактирует/удаляет свой, ставит/убирает лайк. Проверьте спойлеры. Google/Firebase сам по себе не является Community-сессией.
6. Откройте старый тайтл с комментариями: текст, replies, likes сохраняются. Неверные клиентские hints/отсутствующий alias не должны открывать чужую ветку. Проверка ошибок не требует массового создания тайтлов.
7. Запустите серию: выбор источника, воспроизведение, seek, fullscreen/PiP, возврат в карточку. Ошибка/отсутствие сети Community не должна блокировать просмотр или вызывать crash; проверьте кеш и обновление обсуждения.
8. Запишите модель/API устройства, версию/номер run, источник + release ID, время, ожидаемый/полученный результат. Не прикладывайте токены/email/личные данные. Ручной тест не считается пройденным только из-за зелёного CI.

Ни установка, ни live Zero-Touch smoke на реальном телефоне в Codex не выполняются. Полную готовность можно подтвердить только после этих проверок. PR не сливается автоматически.
