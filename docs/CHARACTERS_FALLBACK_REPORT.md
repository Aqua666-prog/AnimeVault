# Загрузка персонажей: Аниметка как резерв Shikimori

Дата проверки: 23 октября 2026 года. Ветка: `fix/characters-animetka-fallback`.
Основание: приложенный пользователем REPORT.md о публичном API Аниметки.

## Изменения

- Добавлены `GET api/anime/{animetkaId}/characters` и
  `GET api/anime/characters/{shikimoriCharacterId}`. Подробная карточка запрашивается
  при открытии персонажа из Аниметки; ошибка оставляет данные списка и кнопку повтора.
- При ошибке, отсутствии сопоставленного тайтла или пустом списке Shikimori
  репозиторий пробует Аниметку. Tenrai продолжает дополнять персонажей и видео.
- Для родного тайтла Аниметки используется внутренний ID. Для другого провайдера
  поиск получает кандидатов, при необходимости запрашивает карточки и принимает
  только совпадение внешнего ID в той же системе. Конфликтующие ID и неоднозначные
  совпадения отклоняются. Сопоставление для персонажей отделено от менее строгого
  текстового поиска трейлеров.
- `character_shikimori_id` сохраняется отдельно от `mal_id`; отсутствие MAL ID
  в списке не восполняется номером Shikimori или совпадением имени.
  Tenrai объединяется с персонажем только по явному MAL ID.
- У персонажа сохраняется источник данных. Роли локализуются, включая `Main` в
  `roles_ru`, и остаются связаны с текущим тайтлом: подробности и другие появления
  персонажа их не перезаписывают. BBCode проходит существующий текстовый санитайзер;
  `description_html` не исполняется и не вставляется в WebView.
- Постеры сохраняют адрес `shikimori.io`. Относительные ссылки нормализуются в HTTPS;
  неподдерживаемые схемы отклоняются. Coil использует отдельный от метаданных дисковый
  кеш `cacheDir/artwork` размером до 128 МиБ. Для `shikimori.io` заданы User-Agent и
  Referer. Ошибка постера имеет отдельную кнопку повтора и не скрывает персонажа.
- HTTP-, GraphQL- и протокольные ошибки не превращаются в успешный пустой список.
  GraphQL-ответ без `data.animes`/`characterRoles` и неверная структура ответа
  персонажей Аниметки считаются ошибкой. Для Shikimori и Аниметки установлен
  общий тайм-аут вызова 25 секунд.
- Отмену coroutine нельзя преобразовать в пустой результат. Ошибки поиска не
  записываются в кеш сопоставления. Агрегат с ошибками не кешируется на два часа;
  подробности кешируются только после проверки идентичности персонажа.
- При неудачном обновлении сохраняется последний успешный список (до 64 тайтлов
  в памяти) с отметкой о прежних данных и возможностью повтора. Ошибка персонажей
  не мешает показать доступные видео. Повтор списка обходит кеш агрегата, Shikimori
  и персонажей Tenrai; во время обновления прежние данные остаются на экране.

## Тесты

Добавлены 28 unit-тестов: 17 для агрегатора, 5 для контракта персонажей Аниметки,
5 для сопоставления и 1 для отказа от кеширования результата с ошибкой.

Проверяются: HTTP 522 и резервный источник, правильный внутренний ID, родной тайтл
Аниметки, проверка неполного поиска через карточку, конфликты внешних ID, разные
пространства Shikimori/MAL, объединение Tenrai по явному MAL ID, роли в разных
тайтлах, успешный пустой список, неверный JSON-контракт, GraphQL errors, отсутствие
данных, восстановление без принудительного обновления, обход успешного кеша при
повторе, сохранение списка при сбое, доступность видео при ошибке персонажей,
отмена coroutine, подробности персонажа и нормализация адресов постеров.

Фикстуры содержат первые четыре записи реального списка Frieren и полную карточку
Ферн. Их происхождение указано в `app/src/test/resources/animetka/README.md`.

эмуляторе и визуальная проверка на устройстве в эту проверку не входят.

в рамках этого исправления не добавлялась.
