# Аудит интерфейса AnimeVault 4.2 → 5.0

База — `aad02e0`, 4.2.0 (86). Обследованы точки входа, активный NavHost, основные экраны и модели состояний, ядро данных и тесты. Визуальная галерея показывает версию 3.0.3. Она помогает увидеть историческую композицию и хром приложения. Актуальные маршруты и состояния ниже сверены с кодом 4.2. [Галерея 3.0.3](../../screenshots/README.md) · [Технический аудит базы](../../ANIMEVAULT_TECHNICAL_AUDIT.md).

## Архитектура и границы

| Слой | Текущий контракт | Что важно при миграции |
|---|---|---|
| Вход и темы | `AnimeVaultApplication` создаёт AppContainer, `MainActivity` отвечает за вход, edge-to-edge, запуск/онбординг, OAuth и PiP | Vault, Midnight, OLED и Dynamic имеют сохранённые значения. Системное отключение движения и API 24–30 fallback входят в контракт |
| Представление | Один `:app`, Kotlin 2.4.10, AGP 9.3.2, Gradle 9.5.0, JDK 17, Compose BOM 2026.06.01, Navigation 2.9.8, Coil 3.5.0. min 24, compile/target 37 | Тестовые экраны в `src/debug`. Дизайн может меняться поверх существующих ViewModel и событий |
| Онлайн | `OnlineRepository`, registry/capabilities, Retrofit 3 + OkHttp и адаптеры, ранжирование, кэши, Tenrai/AniList/Shikimori и транспорт | Ключи provider/release/episode, заголовки потока, язык/озвучка и приоритет источников переходят через прежние контракты |
| Хранение | Room 2.8.4, `AnimeVaultDatabase` v8 (миграции 1→8), Community cache v1, SharedPreferences и DataStore онбординга | Схема, ключи и форматы копии сохраняются. У локального файла может временно пропасть SAF-разрешение |
| Офлайн | `LibraryViewModel` → `LibraryRepository` → SAF/MediaStore, scanner, parser, `LocalTitleRecognizer`, ручная группировка и metadata matching | Локальное распознавание и ручное исправление сохраняют свой приоритет. Документированная реализация использует эвристики и поиск метаданных. [Распознавание](../../LOCAL_RECOGNITION_AND_AUDIO_1.3.md) |
| Загрузки | `DownloadRepository` → WorkManager 2.11.2 → `DownloadWorker`/operation token → `NativeDownloadEngine` → verifier/importer → Room/MediaStore | Пауза, повтор, удаление и запуск привязаны к фактическому состоянию файла. Сохраняются direct/HLS, AES-128, byte ranges, init maps, resume и unique work |
| Плеер | Media3 1.11.0, локальный `PlayerRoute` и отдельный `PlayerActivity`, встроенный online player, downloaded route, session bridge | Владение и release ExoPlayer, MediaSession, аудио DSP, gesture/seek, orientation, PiP, прогресс, автовоспроизведение и recovery остаются у текущих компонентов |
| Обновление и данные | Updater, Firebase/Community и OAuth, `AnimeVaultBackupRepository`, SAF-экспорт/импорт, CSV в библиотеке | Прежние deep links, проверка подписи APK, импорт старых копий, слияние данных и полномочия URI |
| Проверки | JVM fixture tests, Room/WorkManager и Compose instrumentation, Android Studio Preview, workflows сборки, canary и Community | Прототипы используют общий визуальный режим с Roborazzi, который появился в Project Ascension (#62). Запуск реальных источников и устройство относятся к отдельной проверке |

## Маршруты и пользовательские состояния

Сейчас нижняя панель содержит Главную, Каталог, Библиотеку, Загрузки и Настройки. При ширине от 600 dp появляется rail. NavHost сохраняет состояние корневых разделов. Экран распоряжается собственными insets. Discovery-переходы реализованы на моках. Эта таблица задаёт объём будущей интеграции. [AnimeVaultApp.kt](../../../app/src/main/java/com/sergey/animevault/ui/navigation/AnimeVaultApp.kt).

| Маршрут или вход | Действия и источники состояния | Пограничные состояния для нового UI |
|---|---|---|
| `home` | `HomeViewModel`: продолжить local/online, ленты и подборки, поиск, клипы, статистика | Первый вход, без истории, пустая лента, частичная выдача, офлайн с доступным локальным контентом |
| `online` | `OnlineCatalogViewModel`: запрос и история поиска, расширенные фильтры, сортировка, локальные совпадения, источник и play | Загрузка, пустой запрос/результат, частичная выдача, отключённый или недоступный источник, повтор и сохранение позиции |
| `media-title/local/{titleId}` | `TitleDetailViewModel`: локальные серии, метаданные, франшиза, привязка онлайн, воспроизведение | Нет метаданных/постера, потеря доступа, отсутствующая серия, привязка в процессе и ошибка |
| `media-title/online/{providerId}/{releaseId}` | `OnlineTitleViewModel`: серии и источники, списки и пометки, похожие, перевод/качество, скачивание сезона, материалы и обсуждение | Нет серий или перевода, устаревшие метаданные, ошибка резолвинга, локальный дубль, частичная загрузка сезона, гостевой статус |
| `online-library` | `LibraryHubViewModel`: продолжить, локальная/онлайн медиатека, история и управление сохранённым | Пустая коллекция, только один вид данных, фильтр без совпадений, устаревшие локальные строки |
| `offline` | `LibraryViewModel`: выбор папок через настройки/SAF, пересканирование, группировка, локальный тайтл | Нет папки, отказ/отзыв доступа, сканирование, частичный результат, недоступное хранилище |
| `online-saved` | `OnlineLibraryViewModel`: сохранённые релизы, переход в тайтл или плеер | Пустой список, источник выключен, в выдаче устаревший релиз |
| `downloads` | `DownloadsViewModel`: очередь и фильтры, состояние Room, просмотр/повтор/пауза/удаление | В очереди, загрузка, пауза, объединение и проверка, успех, отказ, отмена, отсутствующий файл, нехватка места. Процент сопровождается статусом |
| `history` | `HistoryViewModel`: локальная и онлайн история, продолжить и управлять записями | История пуста, исчез локальный URI, онлайн релиз недоступен, одноимённые тайтлы из разных источников |
| `player/{episodeId}` | `PlayerViewModel`/Media3: подготовка локальной серии, управление, следующая, настройки и PiP | Буферизация, seek, ошибка/отсутствие файла, конец, Back, поворот, восстановление, режим без контролов |
| Онлайн-плеер и просмотр загрузки | Вход из Главной, Каталога, Тайтла, Истории, Библиотеки, Загрузок и Клипов. Activity/Compose overlay, source switching и downloaded route | Изменение дорожки/качества, переключение CDN, полный отказ, офлайн-доступ к проверенному файлу, subs/audio, lifecycle |
| `clips` | `ClipFeedViewModel` + controller: лента, переход к тайтлу/серии | Лента пуста, медиа отсутствует, loading, cancel/stop при уходе |
| `statistics` | `StatisticsViewModel`: локальный/онлайн прогресс | Нет истории и переход к просмотру. Агрегаты сохраняют правила подсчёта |
| `calendar` | Календарь премьер, настройки напоминаний, переход в поиск | Нет расписания, reload, timezone, уведомления запрещены |
| `shikimori-collections` | Подборки и тайтлы → поиск каталога по исходной строке | Загрузка списка, кэш, пустая подборка, недоступный источник |
| `settings` | Настройки внешности, воспроизведения, источников, папок, аккаунтов, резервирования и обновлений | Разрешения, ошибка входа/импорта, устаревшая копия, без активных источников, выход из аккаунта |
| Вне NavHost | Splash/launch gate, onboarding DataStore, внешние OAuth URI, уведомления, обновление, Community UI внутри тайтла | Повторный вход, гость, плохой callback, системная навигация, разрешения, offline, возвращение из другого приложения |

## Что изменилось в прототипах после аудита

| Приоритет | Наблюдение | Проектное решение |
|---|---|---|
| Высокий | История, локальная библиотека и онлайн-список — разные маршруты за хабом, а загрузки имеют корневой вход | Журнал держит три редакционных раздела, Сеанс группирует личные сценарии в «Моё», Индекс выводит «Офлайн» на первый уровень. Снижение видимости загрузок подлежит тесту |
| Высокий | Просмотр стартует из нескольких мест, каждому нужен возврат к исходному контексту | Во всех прототипах отдельный вход в просмотр и Back. В плане миграции задана проверка всего графа включая PiP и downloaded route |
| Высокий | Пустая выдача, сбой источника и отсутствие локального файла требуют разных действий | Поиск на моках демонстрирует пустую выдачу и сброс. Каждый контракт ниже по миграции требует явный recovery для рабочего UI |
| Средний | Историческая композиция повторяет яркое основное действие, округлые панели и подписи поверх искусства | Журнал использует пустое поле и набор, Сеанс отделяет сведения от полноформатного кадра, Индекс убирает крупный декор из рабочих списков |
| Средний | В плеере уже были технические исправления inset/поворота и управления жизненным циклом | Изменение композиции панели проверяется отдельно от Media3 и хранения позиции |
| Средний | Выдача и заголовки русскоязычные, реальные названия также латинские и японские | Системные семейства с fallback, sp, перенос текста, видимый текст статуса и проверка 320 dp / 1.6× |
