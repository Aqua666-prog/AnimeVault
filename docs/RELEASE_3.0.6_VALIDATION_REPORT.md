# Подготовка AnimeVault 3.0.6 (66)

База проверки: `main`, коммит `200fa26`. Работа выполнена в отдельной ветке
`fix/release-3.0.6-validation`.

## Первопричина

В актуальных исходниках `app/build.gradle.kts` обнаружены `versionName = "3.0.5"`
и `versionCode = 65`. Тег `v3.0.6` сам по себе не изменяет версию APK.

Генератор `tools/prepare-update-manifest.py` уже получал версию из вывода
`aapt dump badging` собранного APK. Поэтому старый APK приводил к JSON с теми же
`3.0.5 (65)`. Переписать только JSON означало бы рассогласовать его с APK.
В workflow отсутствовала обязательная проверка против тега релиза; существующая
проверка старой тестовой ветки сравнивала APK и JSON, но не тег.
Сведения о содержимом опубликованного релиза взяты из описания пользователя;
релизные assets в этой задаче не скачивались и не заменялись.

## Изменения

- Версия исходников установлена в `3.0.6 (66)`.
- Сохранена генерация JSON из **того же** `dist/AnimeVault.apk`, который попадает
  в артефакт. `versionName`, `versionCode`, minSdk, имя файла и SHA-256 берутся из
  данных APK, а не из введённых вручную параметров workflow.
- Добавлен `tools/verify-release-version.py` с двумя этапами проверки.
  До сборки объявленная версия исходников сравнивается с тегом.
  После сборки APK и JSON сравниваются с исходниками и тегом; дополнительно
  сверяются поля JSON, пакет, имя файла и SHA-256 APK.
- Для `push` тега `v*` используется реальный `github.ref_name`, для события
  `release.published` — `github.event.release.tag_name`. Добавлены оба триггера.
  Публикация релиза собирает код указанного тега.
- Ручной `workflow_dispatch` требует `release_tag` и собирает выбранный ref.
  Отсутствующий, неверный тег или конфликт введённого тега с выбранным Git-тегом
  приводят к ошибке. Версия из тега не записывается в JSON: тег служит проверкой.
- Обычные push-сборки веток не имеют тега релиза: для них всегда проверяются
  исходники ↔ APK ↔ JSON. Тег не выдумывается из версии APK. Во всех релизных
  запусках (`push` тега, `release`, ручной запуск) тег обязателен.
- Проверка после сборки выполняется без `if` и `continue-on-error`, до загрузки
  артефактов. Неверные APK/JSON/тег дают ненулевой код и останавливают build job;
  шаг загрузки артефактов при этом не выполняется.
- Блоки восстановления существующего keystore из
  `ANIMEVAULT_DEBUG_KEYSTORE_B64`, пароли, alias, настройки Gradle-подписи и
  окружение шага `Build APK` сохранены без изменений. Новый ключ не создавался.
- Функциональность приложения не менялась: в конфигурации Android изменены
  только две строки версии. Исходники приложения не редактировались.

## Результаты лёгких проверок

| Проверка | Результат |
| --- | --- |
| `python3 -m unittest discover -s tools -p 'test_release_version.py' -v` | 13/13 проходят |
| `python3 -m unittest discover -s tools -p 'test_update_manifest.py' -v` | 7/7 проходят |
| Проверка исходников против `v3.0.6` новым CLI | `Verified source: 3.0.6 (66)` |
| YAML, bash и Python: синтаксис | успешно |
| `bash tools/verify-final.sh` | успешно |
| `bash tools/verify-2.0.0.sh` | успешно |
| `git diff --check` | без замечаний |
| Сравнение блоков подписи и сборки с `main` | без изменений |

Тесты используют синтетические байты и фиктивный `aapt badging`, а не настоящий
APK. Проверены: старые APK и JSON под новым тегом, несовпадение имени и кода
версии, пустой/чужой тег, повреждённые поля/хеш, неправильные типы JSON и
двусмысленная версия в исходниках. Выполнены также **реальные bash-команды двух
новых шагов workflow** в временной папке с фикстурами: верный набор проходит,
отсутствие тега, конфликт тегов и старый JSON завершаются ошибкой.
Генератор отдельно проверен на 3.0.4, 3.0.5, 3.0.6 и 3.0.7 — версия не закреплена
за конкретным выпуском.

## Сборка и замена опубликованных файлов

Gradle, Android SDK, эмуляторы и сборка APK в Codex не запускались.
Android unit-тесты, lint и проверка новой подписи APK здесь не выполнялись.
Сборка и `apksigner verify` остаются в GitHub Actions.

После слияния для исправления уже опубликованного релиза нужно запустить
`Build AnimeVault APK` на актуальном `main` с `release_tag = v3.0.6` и использовать
APK и `animevault-update.json` из одного прошедшего проверки артефакта.
Этот PR не публикует assets и не переносит существующие Git-теги.
