# AnimeVault 4.1.0 — Community & Comments

Статус: кандидат для проверки. Исходники не означают готовность production-сервиса. Миграция не применялась к Supabase, реальная доставка email и callback требуют проверки владельцем на устройстве. Встроенный SMTP (2 письма/час на проект, разрешённые адреса команды) блокирует публичную регистрацию. Также нужны production Site URL и защищённые HTTPS App Links.

## Доступ к комментариям в 4.1.1

Вкладка тайтла содержит комментарии, сортировку и редактор в общей LazyColumn. Промежуточная кнопка открытия удалена; диалог используется только для серии и аккаунта. Конфигурация доверенного Actions workflow подключена к публичному проекту владельца. Это не применяет SQL: [запуск, Variables и создание проверенных связей](COMMUNITY_LAUNCH.md).

## Поток данных

`Compose → CommentsViewModel / CommunityAccountViewModel → repositories → CommunityApi (OkHttp REST) → Supabase Auth / PostgREST → PostgreSQL`.

`CommunityServices` создаётся лениво в AppContainer. `CommunityConfiguration` проверяет флаг, точный URL существующего проекта и формат publishable key. Отсутствие конфигурации отображает «Сервис не настроен». Firebase-токены не передаются Supabase.

`CommunitySessionManager` шифрует access/refresh token и ожидающий PKCE verifier через Android Keystore AES-GCM; файлы находятся в `noBackupFilesDir`. Refresh сериализован Mutex; сетевая ошибка не удаляет сессию, отказ refresh удаляет локальные credentials и черновики пользователя. Выход очищает локальную сессию даже при ошибке удалённого отзыва. Новые пароли и email не сохраняются в Room или SavedState.

## Идентичность и контексты

Канонические тайтлы и связи заводит доверенный оператор. Клиент не создаёт и не меняет соответствия. Приоритет: подтверждённый AniList, затем MAL; конфликт идентификаторов возвращает недоступность. На странице провайдера дополнительно требуется проверенная `provider + external_id` связь, которая подтверждает переданные метаданные. Названия в сопоставлении не участвуют.

Серии требуют отдельной проверенной связи `provider + release_id + external_episode_id → community_episodes`. Общий контекст имеет `episode_id = NULL`. Дробные номера, OVA и specials имеют отдельный episode key. Номер файла сам по себе не является подтверждением. Для локальных файлов без доказанного соответствия серия не сопоставляется; общее обсуждение доступно по сохранённому AniList/MAL ID, если каноническая запись уже заведена оператором.

## Комментарии и кеш

Только обычный текст, 1–2000 Unicode-символов после нормализации переносов и удаления внешних ASCII-пробелов. Корень и два уровня ответов. Ответы открываются по уровням, без рекурсивного получения всего дерева; порядок ответов — от старых к новым. Корни сортируются по времени либо серверному числу лайков. Размер страницы 20, серверный максимум 50; offset не больше 10000. Стабильный UUID — ключ LazyColumn.

Публикация использует сохраняемый `client_request_id`; повтор при потерянном ответе возвращает уже созданный UUID. Изменение черновика начинает новую операцию. Лайки задаются как желаемое состояние, а не неидемпотентное переключение; UI обновляется оптимистично и откатывает ошибку. Профиль создаётся/обновляется RPC только для `auth.uid()`.

Спойлер не включается в UI/semantics до раскрытия. Удалённый комментарий остаётся узлом дерева. Скрытый модератором текст никогда не возвращается обычному пользователю. Число комментариев учитывает узлы дерева, включая placeholders; статистика профиля — только visible.

Кеш — до 120 страниц/сопоставлений на 7 дней, до 100 черновиков на 30 дней. Он включает сведения авторов из загруженных страниц, но не чужие email. Состояние личного лайка не сохраняется в публичный кеш. Черновики разделены по UUID аккаунта, контексту и родителю; выход удаляет черновики пользователя. Кеш не является гарантией актуальности модерации: уже загруженный текст может оставаться доступным офлайн до обновления/истечения срока. Редактирование/удаление очищает кеш страниц.

## Обновление и ограничения

REST, обновление при возврате и pull-to-refresh реализованы. Realtime и фоновая отправка офлайн-сообщений не включены. Нет Android-панели модератора, загрузки аватаров, автоматического связывания Firebase, подписок и уведомлений. Аватары — фиксированные placeholders. До публичного запуска нужны шлюзовые лимиты для анонимных чтений и наблюдение за нагрузкой.
