# AnimeVault 0.7.5

0.7.5 продолжает проход 0.7.4 по надёжности и закрывает несколько давно запланированных функций плеера. Схема Room не менялась.

## Плеер

- добавлены вертикальные жесты: левая половина экрана управляет яркостью, правая — громкостью;
- направление жеста фиксируется только после превышения touch slop, чтобы вертикальная регулировка не конфликтовала с горизонтальной перемоткой;
- изменение яркости действует только на окно AnimeVault, громкость меняется через системный music stream;
- операции изменения яркости/громкости защищены от ошибок конкретной прошивки;
- `PlayerView` удерживает экран включённым во время локального и нативного онлайн-воспроизведения;
- добавлен Picture-in-Picture для локального и нативного онлайн-плеера на поддерживаемых устройствах;
- в PiP скрываются собственные элементы управления AnimeVault и штатный контроллер Media3;
- позиция дополнительно сохраняется при `ON_STOP`, а не только по таймеру и при закрытии экрана.

## Автопропуск опенинга и эндинга

- таймкоды задаются вручную и хранятся отдельно для каждого тайтла;
- можно включать опенинг и эндинг независимо;
- начало диапазона можно снять с текущей позиции;
- конец эндинга можно поставить в фактический конец серии;
- поддерживаются форматы `MM:SS`, `HH:MM:SS` и секунды;
- диапазоны проверяются перед сохранением;
- активный автопропуск виден по акцентному значку таймера;
- настройка работает для локальных файлов и нативных HLS/MP4, но не вмешивается во внешний WebView-плеер.

## Онлайн-воспроизведение

- если нативный поток Media3 падает, AnimeVault автоматически пробует следующий вариант;
- приоритет fallback: та же озвучка, затем нативный поток вместо embed, затем более высокое качество;
- уже упавший URL не выбирается повторно в рамках серии;
- ручной выбор потока сбрасывает список неудачных вариантов;
- сравнение названий озвучек сделано locale-safe.

## Онлайн-источники

- в настройках появился health-check каталожных провайдеров;
- показываются состояния «работает», «нужен токен», «недоступен», «проверяется» и задержка успешного ответа;
- проверки идут параллельно и изолируют ошибки отдельных источников;
- Jut.su не включён в массовый health-check, потому что его адаптер работает от URL/slug и пустой запрос не является сетевой диагностикой;
- «Все источники» получил in-memory TTL-кэш каталога, чтобы возврат на экран и повторные запросы не делали полный fan-out каждый раз;
- кэш ограничен по размеру и удаляет старейшие записи после очистки просроченных;
- при изменении токена/сессии кэш единого каталога сбрасывается.

## Инфраструктура

- в архив возвращён Unix `gradlew`, поэтому проект снова одинаково запускается из Android Studio, Linux/macOS shell и Windows wrapper;
- `versionCode 17`, `versionName 0.7.5`;
- схема Room без изменений относительно 0.7.4.

## Проверки

В контейнере выполнены:

- XML parse: 13/13 ресурсов;
- отдельная синтаксическая проверка изменённых Kotlin-файлов компилятором без обнаруженных parser errors;
- smoke-test реальной логики таймкодов/автопропуска;
- smoke-test логики горизонтальной перемотки и вертикальных уровней;
- проверка структуры ZIP после упаковки должна выполняться перед выдачей архива.

Полный Android `assembleDebug` / `testDebugUnitTest` здесь по-прежнему ограничен окружением: wrapper требует Gradle 9.5.0, а контейнер не имеет готового Android SDK/доступа к загрузке Gradle distribution. Перед релизом нужен обычный device-прогон в Android Studio.
