# Первоначальный каталог Community

Для массового импорта без manifest.json используйте [AutoSync v1](COMMUNITY_CATALOG_AUTOSYNC.md). Этот инструмент остаётся для отдельных проверенных ручных соответствий.

База main: e3e0935719ee6267c3b8fd1ea12eb77b39f289ff. Миграция уже применена владельцем; повторно её не запускать. Этот инструмент не меняет схему, RLS, приложение или версию. Он **не подключается к Supabase вообще**: читает публичный AniList, создаёт план и, после проверки оператором, SQL-файл. Запуск SQL владельцем — отдельное действие, не действие агента.

## Что автоматизировано и что требует проверки

`tools/community_catalog/import_catalog.py` принимает AniList ID либо MAL ID. MAL ID разрешается через официальный `AniList Media(idMal)` и проверяется по `idMal`; отдельного MAL API-клиента здесь нет. Тайтл, отсутствующий в AniList, автоматически не импортируется. Указанные одновременно AniList/MAL ID обязаны соответствовать одной записи. Название, год и формат выводятся для проверки, но никогда не служат ключом объединения.

Импортёр не скрейпит все провайдеры и не доказывает достоверность произвольного JSON оператора. Для aliases он проверяет **точные заявленные metadata IDs** против полученной записи AniList, требует ссылку на источник и описание проверки. Оператор обязан открыть источник и подтвердить сведения перед одобрением плана. Если у провайдера нет надёжного external ID, связь не добавлять по похожему названию — canonical запись можно импортировать отдельно.

Для серий AniList episode count недостаточен. Каждый canonical episode key задаётся явно и требует проверенную связь с конкретным provider release и точным episode ID. Совпадение ordinal=1 не доказывает, что это первая серия того же сезона. OVA, фильм, special и дробная серия имеют отдельные ключи и типы. Сервер уже проверяет принадлежность эпизода аниме; импорт не перепривязывает существующие ветки.

## Какие ID нужны для Android

Сверять с фактическими адаптерами: `OnlineReleaseDetails.providerId/id`, `OnlineEpisode.id` и `ExternalAnimeIds.anilistId/malId`. Не использовать локальный Room titleId, URL постера, имя или номер файла. Provider IDs: aniliberty, kodik, animelib, animevost, jutsu, dreamerscast, animedia, animeon, sameband, animebest, yummy, animetka. `all` — отдельный агрегатор с собственным release ID; его ID нельзя автоматически получить конкатенацией ID исходного провайдера.

Для первой связи откройте страницу/API конкретного провайдера и исходник соответствующего адаптера в `app/src/main/java/com/sergey/animevault/data/`: установите, какое поле становится release.id и episode.id. Запишите точный ID, подтверждённый AniList/MAL ID и публичную HTTPS-ссылку без токенов/query/логина. В review_note укажите конкретное поле источника и способ проверки сезона/формата/серии. Если ID в источнике не подтверждён, остановитесь; импортёр не заменяет ручную проверку и не обещает автоматически открыть обсуждения всего каталога.

Для локального тайтла canonical запись может разрешаться непосредственно по сохранённому AniList/MAL ID. Для онлайн-страницы текущий `community_resolve` дополнительно требует verified provider/release alias; для серии — episode alias. Поэтому импорт только community_anime не откроет автоматически все онлайн-обсуждения.

## Запуск с Android через Termux — без Supabase secrets в чате

Используйте актуальный Termux из F-Droid/официального проекта. Не вводите пароли в чат, JSON manifest, GitHub Actions или аргументы команд.

```sh
pkg update
pkg install python git postgresql ca-certificates nano less
termux-setup-storage
git clone https://github.com/Aqua666-prog/AnimeVault.git
cd AnimeVault
```

До слияния PR переключитесь на ветку `feature/community-catalog-import`; после слияния используйте main и `git pull --ff-only`. Версию инструмента зафиксируйте `git rev-parse HEAD` в своём журнале.

1. Выполните `cp docs/community_catalog/manifest.example.json manifest.json`, затем `nano manifest.json` и заполните проверенные данные. В Termux: Ctrl+O → Enter сохраняет файл, Ctrl+X закрывает редактор; Ctrl доступен на дополнительной клавиатуре Termux. Пустые строки в примере специально не проходят проверку. Пример не является готовым соответствием Naruto ↔ AnimeVost и не содержит доказанных provider IDs.
2. Для первого знакомства можно создать отдельный файл с `[ {"anilist_id":20,"mal_id":20} ]`: он импортирует только canonical запись, не придумывая aliases или серии. Для первого онлайн-обсуждения заполните настоящий alias по инструкции выше.
3. Сформируйте план — это только публичные чтения AniList, не запись в Supabase:

```sh
python tools/community_catalog/import_catalog.py plan manifest.json --out plan.json --journal import-errors.jsonl
```

Ограничения: до 100 аниме, входной JSON до 2 MiB, сетевой timeout 25 секунд, последовательные запросы с паузой. При 429/ошибке API запись не угадывается; исправьте/повторите позже. Сетевые ошибки и валидация журналируются кодами с индексом записи, без raw HTTP body и credentials. Любая ошибка блокирует подготовку SQL всего пакета. Повтор plan не пишет БД. Сохраните manifest, plan, журнал и SHA коммита инструмента вне публичного репозитория.

4. Откройте план командой `less plan.json` (q — выйти). Проверьте канонические IDs/сезон/формат, каждый provider ID, release ID, каждый episode key и external episode ID, ссылки и review_note. План **не криптографически заверенная выписка провайдера**: ввод оператора остаётся доверенной административной процедурой. Не одобряйте данные другого пользователя без проверки источников.
5. Команда вывела `Plan SHA256`. Только после проверки явно одобрите **этот** хеш:

```sh
python tools/community_catalog/import_catalog.py sql plan.json --approve-plan-sha256 ВСТАВЬТЕ_ХЕШ_ПЛАНА --out import.sql
```

Это всё ещё не запись в Supabase. Изменение плана меняет хеш и требует нового одобрения. Просмотрите import.sql. В SQL нет Supabase credentials или публичного административного RPC. Для маленького пакета его можно открыть через файловый менеджер и вставить в Supabase SQL Editor проекта `kgvkxocbkklisqrqmcjx`, роль postgres. Для большого пакета удобнее psql из Termux — весь SQL копировать в мобильный редактор не нужно.

6. **Только после отдельного решения применить пакет** возьмите non-secret host/port/user из Dashboard → Connect. Пример-шаблон, не готовая строка подключения:

```sh
psql -W "host=ВАШ_POOLER_HOST port=5432 dbname=postgres user=postgres.kgvkxocbkklisqrqmcjx sslmode=verify-full sslrootcert=$PREFIX/etc/tls/cert.pem" -v ON_ERROR_STOP=1 -f import.sql
```

Пароль вводится в собственном терминале по скрытому запросу psql, не через URI, аргумент, PGPASSWORD в shell history или файл Git. Для проверки сертификата используйте sslmode=verify-full с CA из Dashboard/настройки доверия; не отключайте TLS. При отсутствии прямого IPv6-подключения используйте подходящий pooler из Dashboard. Агент этот шаг не выполняет без вашего подтверждения и доступа.

## Повторный запуск, конфликты и журнал

Весь пакет — одна BEGIN/COMMIT транзакция с общей advisory lock импортёра. Повтор идентичного SQL не создаёт дубликаты и не меняет UUID. Existing canonical IDs, verified aliases, тип/номер episode key и provider episode links проверяются. Любое расхождение вызывает исключение и откат **всего** пакета; никаких автоматических merge, удаления, переименования или переназначения обсуждений. Существующий unverified alias не повышается молча до verified. Недостающий MAL ID у уже существующей canonical записи также требует отдельного рассмотрения, а не автоматического объединения.

Сохраните exit code psql и безопасный код ошибки (`catalog_*`) в собственный операционный журнал с хешем плана и временем. Не сохраняйте строку подключения с паролем или полный dump окружения. Обычные права API не расширяются, комментарии/профили/Auth не изменяются. При конфликте не запускайте DELETE/DROP/TRUNCATE; исправьте источник/план, проверьте существующие IDs и создайте новый одобренный пакет. Перед первым импортом подготовьте backup; откат принятой транзакции — отдельное решение владельца, не массовое удаление каталога с обсуждениями.

## Проверка первого обсуждения

В SQL Editor проверить:

```sql
select public.community_resolve(p_anilist => 20, p_mal => 20);
-- Затем подставить РЕАЛЬНЫЕ IDs из одобренного плана:
-- select public.community_resolve(p_provider => 'animevost', p_external => '<release ID>');
-- select public.community_resolve(p_provider => 'animevost', p_external => '<release ID>', p_episode_external => '<episode ID>');
```

Ожидается anime_id и, для серии, отдельный episode_id/key. NULL означает отсутствие/конфликт проверенной связи, а не необходимость менять RLS. На устройстве откройте **тот же источник и тайтл**, вкладку «Обсуждение» → обновить. Должно появиться честное пустое состояние вместо отсутствующей связи. Войдите в Community, создайте профиль, опубликуйте первый комментарий, прочитайте гостем. В серии проверьте отдельную ветку и отсутствие общего комментария. Если открываете «Все источники», нужен проверенный alias для `all` либо откройте напрямую импортированного провайдера. SMTP/email OTP и реальные Auth/device проверки остаются отдельными условиями запуска.

## Проверки инструмента

Unit-тесты: точные IDs, конфликт AniList/MAL, отсутствие title matching, обязательные основания эпизодов, дубликаты, запрет unknown/private fields, hash approval, ошибки, SQL quoting/dollar delimiters. SQL-тест существующего disposable PostgreSQL runner проверяет повтор, resolve серии и откат конфликта. Реальное API AniList и реальный импорт в Supabase не считаются проверенными тестовыми fixtures. Агент production не изменял.
