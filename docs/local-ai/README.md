# Локальный ИИ: этап 1 — движок MNN

Это подготовка первого этапа, а не готовый ИИ-помощник. Запуск MNN-Pocket-0.3B
ещё не подтверждён. В приложении пока нет экрана чата, загрузчика весов или
ИИ-рекомендаций. Следующие этапы намеренно не начаты до запуска модели — согласно
порядку работ в задании. Не выпускайте эту ветку как готовую функцию.

## Источники и архитектура

Проверен репозиторий https://github.com/Aqua666-prog/AnimeVault, базовый коммит
`12fc546e902f8d4edea2b458376d94eaad990353`, версия приложения 4.2.0 (86).

Приложение: один модуль `app`, Kotlin/Compose/Material 3, навигация в
`ui/navigation/AnimeVaultApp.kt`, зависимости через `AppContainer` в
`AnimeVaultApplication.kt`, Room v8, WorkManager, OkHttp, Media3.
AGP 9.3.2, Gradle 9.5.0, Compose plugin 2.4.10, minSdk 24, compile/targetSdk 37.
Существующие схемы БД, провайдеры, плеер и навигация не изменены.

Добавлен модуль `local-ai`. UI в будущем работает только с `LocalAiEngine`.
Сохранение истории должно принадлежать уровню приложения; движок принимает
историю ролей и перед каждым запросом сбрасывает KV-кеш. Это ограничивает память
и исключает сохранение контекста очищенного диалога внутри runtime. Длинная
история отклоняется по точному числу токенов полного шаблона, а не незаметно
обрезается. По умолчанию: контекст 2048 токенов, ответ до 256.

MNN закреплён git-submodule на коммите
`b0239771b07b317a258fbc384683bbd540741406` (версия в исходниках 3.6.2).
Использован реальный публичный C++ API:

- [llm.hpp](https://github.com/alibaba/MNN/blob/b0239771b07b317a258fbc384683bbd540741406/transformers/llm/engine/include/llm/llm.hpp)
- [Android LlmSession](https://github.com/alibaba/MNN/blob/b0239771b07b317a258fbc384683bbd540741406/apps/Android/MnnLlmChat/app/src/main/cpp/llm_session.cpp)
- [официальная инструкция сборки](https://github.com/alibaba/MNN/blob/b0239771b07b317a258fbc384683bbd540741406/apps/Android/MnnLlmChat/README.md)

`MnnNative` — собственный JNI-мост AnimeVault; он не выдаётся за официальный Java
SDK. Непроверенных Maven-зависимостей MNN нет. Сборка включает LLM, INT4 low-memory
CPU kernels и Transformer fusion, без HTTP-загрузчика MNN, мультимодальности или
GPU. NDK 27.2.12479018, ARM64/API 24, выравнивание ELF LOAD 16 KiB.

Официальная модель: https://huggingface.co/taobao-mnn/MNN-Pocket-0.3B-MNN.
Запрос к её API из среды получил `CONNECT tunnel failed, response 403`:
Hugging Face отсутствует в разрешённых доменах. Поэтому не проверены ни наличие
и ревизия модели, ни лицензия весов, ни состав файлов, размер, хеши и
совместимость конкретного экспорта с runtime. Параметры сборки INT4 сами по себе
не доказывают совместимость модели. Другой моделью она не подменялась.

## Сборка

```sh
git submodule update --init third_party/MNN
sdkmanager 'platforms;android-37.0' 'build-tools;37.0.0' 'ndk;27.2.12479018' 'cmake;3.22.1'
./gradlew :local-ai:testDebugUnitTest :app:compileDebugAndroidTestKotlin
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Нужна штатная локальная Firebase-конфигурация `app/google-services.json`, как и
для основной ветки. Для ИИ ключи и серверы не используются. Веса в APK не входят.
JNI собирается для arm64-v8a: APK с этим модулем требует ARM64-устройство.
Это ограничение текущего прототипа; до пользовательского релиза нужно решить
вопрос отдельных APK/вариантов, чтобы сохранить установку AnimeVault на других ABI.

## Установка модели для инженерной проверки

До появления безопасного загрузчика это только ручной debug-сценарий.
Сначала нужно получить доступ к официальному Hugging Face-репозиторию, проверить
лицензию, закрепить commit SHA и скачать все необходимые файлы одной ревизии.
Сверить размеры и SHA-256 весов с LFS-метаданными этой ревизии; для остальных
файлов закрепить проверенные хеши. Нельзя использовать непроверенные веса или
выдуманный список имён. Сохранять структуру относительных путей из официального
config. Пока эти проверки не выполнены, запуск модели не считается проверенным.

После сборки установите APK через `adb install -r app/build/outputs/apk/debug/app-debug.apk`.
Для debug-проверки поместите проверенный комплект в приватную папку приложения:

```sh
adb shell run-as com.sergey.animevault mkdir -p no_backup/local-ai/model
# Повторить для каждого проверенного файла, сохраняя подкаталоги:
adb shell 'run-as com.sergey.animevault sh -c "cat > no_backup/local-ai/model/config.json"' < /absolute/path/to/verified/config.json
```

Для весов не используйте текстовые преобразования. Путь входного config в тесте ожидается `config.json`; подтвердить
его по официальному комплекту до запуска. Модель лежит в `noBackupFilesDir`, не
попадает в штатный Android backup и удаляется при удалении приложения.
Управления удалением из UI на этом этапе нет.

## Проверка на устройстве

```sh
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=com.sergey.animevault.localai.LocalAiDeviceProbe \
  -Pandroid.testInstrumentationRunnerArguments.runLocalAi=true
adb exec-out run-as com.sergey.animevault cat no_backup/local-ai/probe.json > probe.json
adb shell dumpsys meminfo com.sergey.animevault
```

Тест содержит 20 русских запросов, сохраняет ответы, wall-clock TTFT/время
генерации, счётчики MNN и пиковый PSS всего процесса с интервалом 100 мс.
PSS не равен только памяти модели и может пропустить краткий пик. Скорость
MNN — счётчик генерированных токенов (включая EOS) / время decode из runtime,
а не число UI-фрагментов в секунду. Достоверность этих счётчиков ещё нужно
сопоставить с фактическим запуском. Для сравнения устройств использовать одинаковые
ревизии модели/runtime, лимиты, число потоков (2), температуру устройства и режим питания.

Для проверки offline заранее установить модель и тестовый APK, включить авиарежим,
отключить Wi-Fi, затем запустить тест. Поле `airplane_mode_confirmed_manually`
заполняется человеком: тест не подменяет реальное отключение сети.
Если не указан `runLocalAi=true`, тест пропускается и не является подтверждением
работоспособности. Пустой ответ при настоящем запуске — ошибка, а не успешный тест.

Ручные проверки после первого успешного запуска: отмена во время prefill/decode,
повторная генерация после остановки, unload/load, фон/возврат, процесс recreation,
повреждённые/отсутствующие веса, длинный контекст, low-memory, разные ARM64 CPU.
Остановка кооперативная: текущий prefill или один native token нельзя прервать
мгновенно. `unload()` дожидается native-вызова. Предварительный порог 512 MiB —
консервативная эвристика, а не измеренное требование Pocket. Java OOM и C++
`bad_alloc` преобразуются в ошибку; Android low-memory killer и аварийный abort
внутри сторонней библиотеки в процессе не перехватываются.

## Русский язык

Полноценная поддержка русского не заявляется. 20 запросов подготовлены, но ещё
не выполнены на модели. В `probe.json` поля `human_score_0_to_4` остаются пустыми
до независимой ручной оценки. Оценивать понятность, русский язык, выполнение
инструкции и отказ от выдуманных фактов отдельно. Проверка рекомендаций будет
отдельной после подключения реального каталога; текущий тест без каталога её
не заменяет.

Если качество низкое: сравнить с небольшим многоязычным instruct-экспортом,
официально поддерживаемым выбранным MNN; оценить память и скорость на тех же
устройствах. Альтернатива — LoRA/fine-tuning Pocket на лицензированном русском
диалоговом корпусе с отдельной тестовой выборкой, затем повторный MNN-экспорт,
INT4-квантизация и полная регрессия. Успех любого варианта пока не подтверждён.

## Следующие этапы после подтверждения запуска

1. Закреплённый манифест официальной модели: размеры, SHA-256, лицензия, атомарная
   установка в приватную папку, отмена и HTTP Range resume с проверкой ревизии,
   проверка свободного места, удаление после `unload()`.
2. Экран установки/чата в существующей дизайн-системе, lifecycle-владелец движка,
   потоковые ответы, остановка, сохранённая история и её очистка.
3. Поиск через существующий `OnlineRepository.getCatalog` и локальную библиотеку,
   фильтрация релевантности до модели. Карточки строить только из объектов
   каталога и открывать существующий route. Свободный текст маленькой модели
   нельзя считать защитой от галлюцинаций: нужен проверяемый формат идентификаторов
   и отклонение результатов вне набора кандидатов. Пустой результат/ошибка
   провайдера должны иметь разные сообщения. Поиск онлайн-каталога требует сети;
   inference и поиск по уже сохранённым данным работают локально.
4. Полный цикл 20+ запросов на русском, device QA, отчёт производительности и
   регрессия плеера, загрузок, каталога, offline-библиотеки и настроек.
