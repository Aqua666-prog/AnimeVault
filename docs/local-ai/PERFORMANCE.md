## Методика следующего прогона

`LocalAiDeviceProbe` сохраняет `no_backup/local-ai/probe.json`. До прогона указать
ревизию модели и контрольные суммы, модель устройства/SoC, объём RAM, Android,
температуру и режим питания. Запустить три холодных load и три прогретых прогона
при одинаковом контексте и лимите ответа. Отдельно фиксировать PSS до загрузки,
после загрузки, пик и после unload. Счётчики runtime сравнить с wall-clock.

Проверки lifecycle и отмены проводить отдельно от языкового набора. Проверку
русского оценить человеком: 0 — непригодно, 1 — частично понятно, 2 — заметные
ошибки, 3 — пригодно с небольшими ошибками, 4 — точный и естественный ответ.
Ненулевое количество токенов и успешный тест не означают качественную поддержку
русского или корректность фактов. Для рекомендаций нужен отдельный набор
проверенных кандидатов каталога и контроль идентификаторов в ответе.

## Проверка native-кода на машине сборки

Успешно выполнена standalone CMake/Ninja-сборка `animevault_ai` и `MNN`
с NDK 27.2.12479018 для `arm64-v8a`, Android API 24, Release. Финальная
пересборка JNI после добавления метрик тоже успешна. `llvm-readelf` подтвердил
ELF64/AArch64 и `Align 0x4000` у LOAD-сегментов обеих библиотек.
`llvm-nm` подтвердил все шесть JNI-методов: create, begin, step, finished,
metrics, release. Это проверка компиляции и линковки, не запуска модели.

После сообщения об опубликованной новой конфигурации повторно проверена текущая
среда: `spec_revision=1`, `observed_spec_revision=1`, policy state `enforced`,
Hugging Face в effective allowlist отсутствует. Свежий запрос 2026-11-09
17:21:32 UTC к
`https://huggingface.co/api/models/taobao-mnn/MNN-Pocket-0.3B-MNN`
снова получил HTTP CONNECT 403 от proxy/envoy. Это блокировка соединения до
получения HTTP-ответа от Hugging Face, а не доказательство отсутствия репозитория
модели или необходимости API-ключа. Нужен экземпляр среды с новой конфигурацией.


## JVM-проверки

- `:local-ai:compileDebugKotlin` — успешно.
- `:app:compileDebugAndroidTestKotlin` — успешно, включая probe из 20 запросов.
  Это компиляция теста, не выполнение модели.
- `:local-ai:testDebugUnitTest` — 4 теста, 0 ошибок/пропусков.
- `:app:testDebugUnitTest` с Java 17 launcher — 634 теста, 0 ошибок/пропусков.

Компиляция выполнялась Temurin JDK 21.0.13; JVM-тесты — Temurin JRE 17
через локальный Gradle init script, задающий `Test.javaLauncher` версии 17,
в соответствии с Java 17 в CI репозитория. Первичный прогон на Java 21 дал
631/634: три ошибки русского разбора в неизменённом `EpisodeNameParserTest`.
Изолированное выполнение одних и тех же 11 скомпилированных тестов дало
11/11 на Java 17 и 8/11 на Java 21. Причина — различие поведения `\b` для
кириллицы в Java regex; парсер и его тесты идентичны базовому коммиту.
В рамках ИИ-интеграции код парсера не менялся.
